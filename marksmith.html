ARCHITECTURAL CAPABILITIES

Engineered for Zero Corruption & Maximum Fidelity

Word's rendering engine is notoriously fragile. MarkSmith was built from the ground up to strictly obey the ECMA-376 OpenXML schema with mathematical guarantees.

ShapeForge™ Vector Engine

ShapeForge™ Diagram Engine

Translates Mermaid flowcharts, mindmaps, state diagrams, and Gantt charts into native Word grouped vector shapes (<wpg:wgp>). Never a blurry PNG. In Word, click any node to drag it, recolor it, or edit text directly.

<wpg:wgp><wps:wsp><wps:spPr><a:prstGeom prst="roundRect"/>...
Native OMML Equations

Native OMML Equations

Translates complex LaTeX math expressions directly into native Microsoft Office Math elements (<m:oMath>) with literal whitespace preservation (xml:space="preserve"). 100% editable inside Word's Equation Tools.

<m:oMath><m:r><m:t xml:space="preserve">\mathbf{M} = ...</m:t></m:r></m:oMath>
AI Export Sanitizer

AI Prompt & Citation Sanitizer

Pasting raw ChatGPT or Claude exports breaks Word converters with unparsed [12†source] citation pips, leaked :contentReference tags, and raw \( \) delimiters. MarkSmith normalizes the AST before Word ever sees it.

Regex Sanitizer: [12†source] & \( \theta \) → Cleaned Word AST
.dotx Master Injection

Corporate Template Injection

Injects compiled Markdown runs into existing corporate .dotx / .docx masters. Automatically inherits company fonts, heading hierarchies, cover pages, headers, and footers without manual formatting overhead.

<w:style w:type="paragraph" w:styleId="Heading1"><w:rPr><w:rFonts w:ascii="..."/>
ECMA-376 Governance

Zero-Corruption Guarantee

Word throws "The file is corrupted" errors whenever relationship IDs (rId) are hardcoded or namespaces are omitted. MarkSmith guarantees valid ECMA-376 schema generation with dynamic relationship management and $O(1)$ SAX streaming via OpenXmlWriter.

Namespaces: w:, a:, wp:, m:, wpg:, wps: | Dynamic rId in .rels
KPI Cards & Geometry

Executive KPI Cards & Proportional Tables

Compiles :::metrics blocks into multi-column executive card grids with 24pt bold metrics, rounded shaded panels, and muted subtitles. Calculates dynamic proportional column widths across w:gridCol and w:tcW for rock-solid, zero-clipping table typography.

<w:tcW w:w="4800" w:type="dxa"/><w:gridCol w:w="4800"/> (Zero-Clipping)

SuperDoc is not a converter, and that cuts both ways

It is a DOCX editor and agent SDK — the file already exists, and a person or an agent changes it. Six of the original eight rows were chosen where a generator naturally wins, so the table flatters MarkSmith by measuring SuperDoc at something it never set out to do. Saying that plainly is what makes the rows that do matter believable.

Where MarkSmith genuinely leads

Generating diagrams, SmartArt and math from plain source text, with contrast enforced on the way out. SuperDoc has no authoring path for any of it.

Where SuperDoc genuinely leads

Round-trip editing, track changes, comments and real-time collaboration — plus a Python SDK and an MCP server. MarkSmith has none of these.

Memory & Local Performance

MarkSmith compiles directly in-memory via .NET 8, eliminating COM overhead and generating full multi-page OpenXML documents in milliseconds.

How each capability was evaluated

MarkSmith capabilities were verified against the production MarkSmith.Core engine: ContrastGuard, GloxBuilder, LatexToOmml and the .dotx template path all run natively in .NET 8. SuperDoc capabilities derive from its technical documentation and repository specifications. Pandoc capabilities derive from its official manual and the texmath docx writer.
